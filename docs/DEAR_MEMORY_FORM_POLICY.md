# Dear Memory 계약 정책·폼 정리

## 목차

1. 확정된 금액 정책
2. 필드 분류와 필수 여부
3. 확인한 모순과 정리 내용
4. 상품 구성 대조 및 확인 필요 목록
5. 변경 범위와 검증

## 1. 확정된 금액 정책

사용자가 이번 작업에서 명시한 업무 기준이다. 현재 Config와 가격 계산은 모두 일치하므로 금액은 변경하지 않는다.

| 구분 | 값 | 계산 시점 |
|---|---:|---|
| 실속형 | 1,250,000원 | 계약 기본가 |
| 화보형 | 1,450,000원 | 계약 기본가 |
| 2인 촬영 | +250,000원 | 즉시 가산 |
| 폐백 | +100,000원 | 즉시 가산 |
| 메이크업 추가 옵션 | 없음 | 선택 및 가격 적용 불가 |
| 짝꿍 | -50,000원 | 즉시 할인, 유효한 짝꿍 정보 필요 |
| 일요일 | -100,000원 | 날짜 기준 자동 즉시 할인 |
| 포트폴리오 | -100,000원 | 동의 시 즉시 할인 |
| 계약 후기 | 50,000원 | 확인 후 추후 Cashback |
| 본식 후기 | 50,000원 | 확인 후 추후 Cashback |

후기 Cashback은 계약총액·계약금·잔금을 미리 줄이지 않는다. 수동 금액 조정은 기존 대표 권한으로 유지한다.

## 2. 필드 분류와 필수 여부

현재 계약 생성·접수·검토·발송 코드의 사용처를 기준으로 분류했다. 촬영 준비 단계의 업무 필요성과 계약 제출 필수 여부를 구분한다.

| 분류 | 필드 | 실제 사용처 | 정리 후 |
|---|---|---|---|
| 계약서에 필요 | weddingDate, weddingTime, weddingVenue, weddingHall | 일정, Review, PDF, 이메일 | 필수 유지 |
| 계약서에 필요 | groomName, groomPhone, brideName, bridePhone | 계약 당사자·연락처, PDF, 이메일 | 필수 유지 |
| 계약 자동화에 필요 | email | 공식 계약서 수신 | 필수 유지 |
| 계약 내용에 필요 | productId, optionIds | 상품 구성·가격·Snapshot | 상품 필수, 옵션 없음 허용 |
| 계약 조건 | partnerDiscount, partnerName | 짝꿍 검증·즉시 할인 | 할인 선택 시 짝꿍 정보 필수 |
| 계약 조건 | sundayDiscount | 날짜에서 서버가 산출 | 별도 고객 입력 없음 |
| 계약 조건 | portfolioConsent | 즉시 할인 및 공개 동의 | 선택 |
| 향후 혜택 | reviewContractCashback, reviewMainCashback | 향후 Cashback 금액 | 선택, 현재 금액과 분리 |
| 계약 동의 | termsAgreed | 접수 차단·약관 기록 | 필수 유지 |
| 계약 특약 가능 | requestNotes | 대표 검토·최종 PDF 별첨·이메일 | 선택 입력 유지 |
| 향후 촬영 준비 | makeupLocation | 대표 알림·Review 참고정보; 가격·고객 PDF에는 미사용 | 필수 해제, 접힌 선택 영역 |
| 향후 촬영 준비 | groomFamilyMembers, brideFamilyMembers | 가족사진 준비; 대표 알림·Review; 고객 PDF/고객 메일에는 미포함 | 필수 해제, 접힌 선택 영역 |
| 향후 촬영 준비 | shootRequestNotes | 촬영 요청; 입력 시 최종 문서에도 반영 | 필수 해제, 선택·후속 확인 가능 |
| 향후 촬영/후보정 준비 | retouchRequestNotes | 보정 요청; 입력 시 최종 문서에도 반영 | 필수 해제, 선택·후속 확인 가능 |
| 계약 자동화에 불필요 | referralSource | 운영 유입경로 참고정보, 금액 계산에 미사용 | 필수 해제, 접힌 선택 영역, 선택 취소 가능 |
| 추후 후기 확인 | instagramId, blogUrl | 대표 참고·후기 확인; 고객 PDF에는 미사용 | 기존 선택 입력 유지, 접힌 영역 |
| 대표 계약 조정 | manualAdjustment | 대표만 수정, Snapshot·PDF·메일 | 기존 권한과 검증 유지 |

예식·고객정보의 필수 입력은 기존 15개 항목에서 9개로 줄였다(달력 선택 포함). 자동 선택되는 기본 상품과 약관 동의는 별도로 유지된다. 짝꿍 할인 사용 시 조건부 입력도 유지된다.

필드는 삭제하지 않는다. 기존 canonical payload·저장 기록·토큰·Snapshot·Review의 데이터 구조를 유지한다. 이미 입력한 선택 정보는 접거나 이전 화면으로 돌아가도 부모 폼 상태에서 보존된다. 촬영/보정 요청을 입력하면 기존대로 대표 검토와 최종 문서에 남는다. 이 작업에서 별도 촬영 준비 수집 시스템을 만들지는 않는다.

## 3. 확인한 모순과 정리 내용

### 메이크업 옵션 제거 후 장소 필수

OPTIONS_CONFIG에는 메이크업 옵션이 없다. makeupLocation은 금액 계산과 고객 PDF에 쓰이지 않고 대표의 준비 참고정보에만 쓰인다. 서버 canonicalForm도 선택값이다. 고객 page.tsx의 필수 검증과 화면 별표만 남아 있었으며, 옵션 제거 이후에도 필수로 둘 업무 근거는 코드에서 확인되지 않았다. 실제 과거 도입 이유는 확인 필요다. 선택 준비정보로 정리하고 미정 입력도 강제하지 않는다.

### 준비/마케팅 정보의 고객 화면 필수 조건

가족 구성 2개·촬영 요청·보정 요청·유입경로는 서버에서 선택값인데 고객 화면에서는 필수였다. 이 5개와 메이크업 장소를 합한 6개 입력칸의 제출 차단을 제거하고 필수 별표와 안내를 정리했다.

### Cashback 안내와 계산의 충돌

가격 계산은 향후 Cashback을 분리했지만 고객 혜택·최종 확인·대표 Review·PDF에는 “잔금 차감 또는 페이백” 안내가 있었다. 이번에 확정된 추후 Cashback 기준으로 정리했다. 계약총액·계약금·잔금 계산은 변경하지 않았다.

### 상품 선택 화면의 별도 앨범 사양

상품 선택 화면에서 실속형/화보형 앨범 규격·권수가 별도로 하드코딩되어 있었다. 이미 있는 Config의 coupleAlbumSummary, parentAlbumSummary, plusBenefits를 읽도록 정리했다. 앨범 수량·규격 자체는 바꾸지 않았다.

### 기타 코드 정리

- 예식 시간 입력 안내를 서버가 받는 24시간 HH:mm 형식으로 맞췄다.
- 옵션 타입 설명에서 제거된 makeup_scene 예시를 정리했다.
- 수동 조정액이 없을 때 PDF 표에 단독 0이 표시되는 조건식을 boolean으로 정리했다.
- 접힌 입력은 native details/summary를 사용한다. 상품 선택은 키보드로도 사용할 수 있는 button으로 정리했다.

## 4. 상품 구성 대조 및 확인 필요 목록

대조 자료는 보존 원본 `work/Dear_Memory_Booking-baseline`의 Config/안내 컴포넌트, 현재 복제본 Config/컴포넌트, 이전 감사·수정 문서, 이번 사용자 금액 기준이다. 별도 업체 승인 상품표나 원본 상담 자료가 제공되었다고 가정하지 않는다.

| 항목 | 보존 원본/기존 안내 | 현재 코드 | 판단/조치 |
|---|---|---|---|
| 상품 기본가·옵션·할인 | 이번 사용자 기준과 일치 | 동일 | 확정, 유지 |
| 실속형 부부 앨범 | 15×12 70p 1권, 부모님 앨범 미포함 | 동일 | 코드 간 일치. 이번에 제공 규격 재승인 자료는 없음; 유지 |
| 실속형 보정/원본 | 보정 70장, 원본 2,000장 이상 | 동일 | 코드 간 일치, 유지 |
| 화보형 앨범 | 부부 15×12 80p 1권 + 부모님 12×8 40p 2권 | 동일 | 코드 간 일치, 유지 |
| 화보형 보정 수량 | 원본 Config 70장; 원본 안내는 +10장 추가 | 현재 70+10장, PDF 총 80장 | **확인 필요**, 현재 값을 유지 |
| 화보형 원본 수량 | 원본 Config 2,000장 이상; 원본 안내 2,500장 이상 | 현재 2,500장 이상 및 +500장 안내 | **확인 필요**, 현재 값을 유지 |
| 화보형 +500장 의미 | 원본 안내에 추가 제공 표현 | 2,500장 이상과 +500장을 함께 표시 | 총 2,500장의 기준 차이인지, 추가로 3,000장을 뜻하는지 **확인 필요**. 임의 합산/변경하지 않음 |
| 계약 후기 허용 채널 | 할인 Config는 다이렉트 예시 포함; 선택 화면은 다이렉트웨딩카페 제외 | 충돌이 남아 있음 | **확인 필요**, 어느 쪽도 임의로 확정/변경하지 않음 |
| 후기 지급 조건·지급 시점·지급 방법 | 정성 후기/결과물 수령/대표 계좌 지급 등 기존 안내 | 유지 | 금액과 추후 지급만 이번에 확정. 세부 증빙·기한·방법은 **확인 필요** |
| 연회장 촬영 시간 | 선택 화면·PDF 10~15분 | 유지 | 이번 사용자 기준에 시간 제한 없음, 변경하지 않음 |
| 계약금·납품·보관·약관 | 계약금 30만원 및 기존 약관 Config | 유지 | 이번에 재확정된 범위가 아니므로 임의 변경하지 않음 |

미확정 수량을 원본 Config로 되돌리거나 현재 값에서 증가시키지 않는다. 현재 기본값은 이전 단계에서 기존 안내와 맞춘 값이지 이번에 승인된 업체 제공 수량이라는 뜻은 아니다. 별도 승인 자료가 확보되면 해당 값과 관련 문구·테스트 기대값을 함께 갱신한다.

## 5. 변경 범위와 검증

별도 복제본에서 고객 입력 조건·선택 영역·Cashback 안내·상품 선택 표시만 정리한다. 원본 저장소, 실제 운영 데이터, 인증·토큰·계약 ID·GAS 저장/발송 로직은 변경하지 않는다. White-label 기능·업체 관리자·후속 준비정보 수집 기능을 추가하지 않는다.

현재 금액 정책·메이크업 옵션 거절·최소 정보 API 접수·필수 정보 및 약관 유지·선택 입력 보존을 회귀검증한다. 기존 가격 256개 조합, 타임존, 중복 방지, 토큰, GET 안전성, 실제 PDF·두 첨부 일치 검증도 유지한다.
